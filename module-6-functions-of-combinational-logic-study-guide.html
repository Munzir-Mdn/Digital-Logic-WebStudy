5. Full Adder

A full adder accepts two input bits plus an input carry (Cin). It generates a Sum and an output Carry. The module states that it is suitable for multi-bit addition by cascading full adders.

Σ = (A ⊕ B) ⊕ Cin

7. Adder / Subtractor Circuit

The module includes an adder/subtractor circuit for 2's-complement arithmetic. A control input S determines whether the B inputs are passed unchanged or complemented through XOR gates, while the initial carry is also controlled by S.

8. Parallel Binary Adder

Two or more full adders connected together form a parallel adder. The carry from a lower-order stage becomes the carry input to the next stage.

Example in the module:
  101
+ 011
= 1000

The module also introduces the MSI chip 74LS283 as a 4-bit parallel adder.

9. Ripple Carry Adder

In a ripple carry adder, the Cout of each full adder is connected to the Cin of the next higher-order stage.

LSB Full Adder → Carry → Next Full Adder → Carry → ... → MSB

The carry accumulates from the lowest-order bit to the highest-order bit. The module emphasizes that the speed is limited by the time required for the carry to propagate through all stages.

10. Look-Ahead Carry Adder

The look-ahead carry adder speeds up addition by eliminating the ripple-carry delay. It anticipates the output carry based on the inputs using carry generation or carry propagation.

Ripple CarryLook-Ahead Carry
Carry propagates stage by stage.Anticipates carry.
Speed limited by propagation delay.Designed to speed up addition.
Module example: 1010 + 0011 = 1101.

12. Multi-bit Comparator

For equality, compare corresponding bits and combine their equality results. The module introduces 74LS85 as a 4-bit comparator.

Comparison strategy shown in the slides: compare the higher-order bits first. If they are equal, continue to the next bits. Once one higher-order pair establishes greater/less, stop comparing lower bits.
Exercise 6.3: A = 1011 and B = 1010 → A > B = 1, A = B = 0, A < B = 0.

13. Decoder — Core Function

A decoder detects the presence of a specified combination of input bits and indicates that code using a specified output level.

n input lines → up to 2ⁿ output lines.

Decoder types listed in the module:

  • 3-bit binary decoder: 3-line to 8-line
  • 4-bit binary decoder: 4-line to 16-line
  • BCD-to-Decimal decoder
  • BCD-to-7-segment decoder

14. Active-HIGH vs Active-LOW Decoder

16. 4-Bit Decoder — 74HC154

The module identifies 74HC154 as a 1-of-16 decoder with four active-HIGH inputs and sixteen active-LOW outputs. It also has two active-LOW enable inputs.

Enable matters: The device must be enabled before the selected output behaves as expected.

21. Encoder

An encoder performs the opposite function of a decoder. A binary encoder encodes information from 2ⁿ inputs into an n-bit coded output, reducing the number of bits needed to represent the information.

The module lists:

  • Decimal-to-BCD Encoder
  • Priority Encoder

22. Decimal-to-BCD Encoder

The example uses 10 decimal inputs and 4 BCD outputs. A HIGH decimal input is converted to the corresponding four-bit BCD code.

The module notes that a separate 0-digit input is not required in the basic logic diagram because the BCD outputs are all LOW when there are no HIGH inputs.

23. Limitation of the Basic Encoder

Exercise 6.6 asks what happens when inputs 2 and 9 are HIGH simultaneously and asks for the restriction on the encoder logic. This leads directly into the next topic: the priority encoder.

24. Priority Encoder — 74HC147

The module states that 74HC147 performs the encoding function with an additional feature: it produces the BCD output corresponding to the higher decimal-value input and ignores the lower value.

Example from the module: if inputs 9 and 5 are LOW simultaneously, only 9 is recognized because it has higher priority.

25. Multiplexer (MUX)

A multiplexer allows digital information from several sources to be routed onto a single line. The module calls it a Data Selector.

Many inputs → ONE selected input → ONE output

The select lines determine which input is connected to the output.

Module relationship: 2¹ select combinations → 2 data inputs; 2² select combinations → 4 data inputs.

28. 74LS151 Multiplexer

The module introduces 74LS151 as a 1-of-8 MUX. In addition to data inputs and selector pins, the IC has an enable pin.

Module note: the enable input is active LOW; logic 0 is applied to enable operation.

29. Demultiplexer (DEMUX)

A DEMUX performs essentially the reverse multiplexing function. It takes digital information from one line and distributes it to a selected output line. The module calls it a Data Distributor.

ONE input → selector chooses → ONE of many outputs

32. Decoder as DEMUX

The module states that a decoder can also be used as a DEMUX. It specifically demonstrates 74HC154 as a 4-bit decoder used as a DEMUX, depending on how its enable/data input is connected.

33. Code Converter

The purpose of a code converter is to convert from one type of code to another.

Examples given in the module:
• 3-to-8 decoder: binary number → one-hot encoding
• 8-to-3 encoder: performs the opposite conversion
• BCD-to-7-segment decoder: another common code-converter example

34. Parity Generators / Checkers

The module explains that errors may occur while digital codes are transferred: a 1 may change to 0 or a 0 may change to 1. Undetected errors can cause problems in a digital system.

Basic parity logic is used to determine whether the number of 1s or 0s is odd or even.

Modulo-2 addition → XOR
Even number of relevant 1s → XOR result 0
Odd number of relevant 1s → XOR result 1

35. Parity Checker

The final slide states that when the circuit is used as an odd parity checker, the number of input bits is always even; when parity error occurs, the Σ-even output goes LOW and the Σ-odd output goes HIGH.

36. Even Parity Generator

For the even parity generator described in the module, the parity bit is taken at the Σ-odd output:

If input contains an even number of 1s → parity bit = 0
If input contains an odd number of 1s → parity bit = 1

39. Common Mistakes

  • Confusing Half Adder with Full Adder and forgetting Cin.
  • Writing Cout of a half adder as XOR instead of AND.
  • Ignoring carry propagation in a parallel/ripple adder.
  • Comparing lower comparator bits before higher-order bits when deciding magnitude.
  • Confusing encoder and decoder directions.
  • Forgetting whether decoder outputs are active HIGH or active LOW.
  • Forgetting that a 3-bit decoder has 2³ = 8 possible outputs.
  • Confusing MUX with DEMUX.
  • Reading selector bits in the wrong order.
  • Ignoring enable pins on MSI devices.
  • Assuming a basic encoder can correctly resolve multiple simultaneously active inputs.
  • Confusing ordinary binary representation with BCD digit-by-digit representation.

40. Mini Quiz

Q1. What are the Half Adder equations?

Σ = A ⊕ B; Cout = AB.

Q2. What additional input does a Full Adder have?

Cin.

Q3. What limits the speed of a ripple carry adder?

The time required for carry to propagate through the stages.

Q4. Which gate is associated with equality comparison?

XNOR.

Q5. How many outputs can a 3-bit decoder have?

2³ = 8.

Q6. Input 101 is applied to the module's 3-bit decoder. Which output is selected?

Q5.

Q7. What does an encoder do?

Encodes an active input into an n-bit coded output; the module describes it as the opposite function of a decoder.

Q8. What is the difference between a normal encoder and a priority encoder?

The priority encoder resolves multiple active inputs by giving priority to the higher-value input, as shown for 74HC147.

Q9. What is another name for a MUX?

Data Selector.

Q10. What is another name for a DEMUX?

Data Distributor.

Q11. For a 1-of-4 MUX, S1S0 = 10. Which input reaches Y?

D2.

Q12. What is decimal 43 in BCD according to the module example?

0100 0011.
