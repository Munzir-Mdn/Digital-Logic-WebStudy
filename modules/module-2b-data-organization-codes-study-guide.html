SECR1013 Digital Logic — Module 2b: Data Organization (Codes)

1. Overview

This module covers data organization into bits, nibbles, bytes and words, followed by BCD, Gray code, parity code and ASCII.

3. Codes

A code represents information according to defined rules. The slides emphasize uniqueness, ease of processing/representation and communication where ordinary written or spoken language is difficult.

4. Binary Coded Decimal (BCD)

BCD represents each decimal digit separately using a 4-bit binary code. Valid decimal digits are 0–9; therefore 1010–1111 are invalid BCD digit codes.

Example: 4509 → 4=0100, 5=0101, 0=0000, 9=1001 → 0100 0101 0000 1001.

5. Gray Code

Gray code is arranged so that every transition from one value to the next changes only one bit. The module relates it to preventing false output from electromechanical switches and error-related applications in digital communication.

Binary → Gray

Maintain the MSB. Each following Gray bit is obtained from adjacent binary bits using addition/XOR while discarding carries.

Gray → Binary

Maintain the MSB. The module's rule uses the preceding binary result with each next Gray bit to determine the next binary bit.

6. Parity Code

A parity bit is added for bit-error detection. In the module, it is appended at the leftmost/MSB position.

Current number of 1sEven parity bitOdd parity bit
Even01
Odd10
Suggested mnemonic: “Parity wants its name” — even parity makes the total number of 1s even; odd parity makes it odd.

7. Error Detection by Parity Checking

The sender adds the required parity bit. The receiver recounts the 1s. If the received parity does not conform to the selected even/odd rule, an error is detected.

8. ASCII

The slides define ASCII as American Standard Code for Information Interchange and present it as a 7-bit binary code with 128 characters/symbols. A parity bit can be added to form 8 bits.

Module example: character A = 1000001₂; lowercase a = 1100001₂.

9. What to Remember for Exam

  1. 4 bits = nibble, 8 bits = byte, 16 bits = word.
  2. Know MSB vs LSB.
  3. BCD encodes each decimal digit independently.
  4. Gray-code neighboring values differ by one bit.
  5. Know both Binary ↔ Gray conversion procedures.
  6. Memorize the even/odd parity table.
  7. ASCII in this module is 7-bit; parity can extend it to 8 bits.

10. Common Mistakes

  • Converting an entire decimal number directly to binary and calling it BCD.
  • Accepting 1010–1111 as valid BCD decimal digits.
  • Changing the MSB during the first step of Binary ↔ Gray conversion.
  • Confusing even parity with “parity bit must be 0”; the required bit depends on the existing count of 1s.
  • Forgetting the module places the parity bit at the MSB.

11. Practice + Model Answers

Q1. Convert 4509 to BCD.

Answer: 0100 0101 0000 1001.

Q2. Convert binary 11010100₂ to Gray code.

Answer: MSB remains 1; XOR adjacent binary bits → 10111110.

Q3. Convert Gray 01011001₂ to binary.

Answer: 01101110₂.

Q4. Data contains an odd number of 1s. What parity bit is required for even parity?

Answer: 1, making the final count of 1s even.

Q5. Why is Gray code useful according to the module?

Answer: Consecutive values differ by only one bit, helping prevent false outputs in electromechanical switching and supporting error-related applications.

Q6. What is the relationship among nibble, byte and word?

Answer: Nibble = 4 bits; byte = 8 bits = 2 nibbles; word = 16 bits = 2 bytes.
